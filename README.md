## 여는 법

공개 주소를 열거나, 받아서 `index.html`을 더블클릭한다. 설치 · 서버가 필요 없고, 글꼴 · 그림이 모두 이 폴더에 있어 인터넷 없이도 열린다.

| 키 | 무엇 |
|---|---|
| ← → (스페이스) | 넘기기 |
| F | 전체 화면 |
| S | 발표자 창: 지금 장 · 다음 장 · 대본 · 시계 |
| N | 대본을 화면 아래에 잠깐 보기 |
| O | 한눈에 보기 |
| 주소 끝 `#/5` | 5장으로 바로 |

- 인쇄(⌘P)하면 한 장에 한 슬라이드가 나온다. "배경 그래픽"을 켠다.
- 화면 비율이 달라도 넘치지 않는다: 16:10 · 4:3은 캔버스가 아래로 늘고, 16:9보다 넓으면 가운데에 놓인다.

## 고치는 법

1. 브랜치를 따서 고치고, `index.html`을 브라우저로 직접 열어 본다.
2. PR을 연다. `pages` workflow가 덱이 부르는 파일이 다 있는지, 키 · 계정 번호 모양이 없는지 검사한다.
3. `main`에 병합하면 같은 workflow가 github.io에 저절로 올린다(1 ~ 2분).

커밋 작성자 메일은 GitHub noreply 주소를 쓴다. 공개 저장소라 커밋에 적힌 메일도 누구나 본다.

## 17장 녹화 찍는 법

17장은 `media/portal-demo.mp4`가 있으면 그 장에 올 때 저절로 재생하고(소리 없음), 없으면 "녹화본 자리"를 보여 준다.

**누가:** 포털 계정이 있고 서버를 만들어도 되는 사람(배포 담당). 진짜 AWS 서버가 만들어지고 돈이 든다. 찍기 전에 팀 대화방에 "지금 만듭니다"라고 말한다.

**준비**
- 화면 녹화 크기 1920x1080, 브라우저 창 하나만. 다른 탭 · 북마크 줄 · 알림은 끈다.
- **포털에 로그인한 뒤부터 찍는다.** 로그인 화면 · 일회용 번호는 찍지 않는다.
- 주소 줄은 찍지 않는다(창 안쪽만 녹화하거나, 다 찍은 뒤 위쪽을 잘라 낸다).

**차례 (찍는 것)**
1. 포털 첫 화면 → **만들기** → **Floe 소개 페이지 서버 (EC2 + EBS)**
2. 양식 네 칸: 배포 이름 · 주소 · 서버 크기(t3.micro) · 디스크 크기(8GB)
3. **미리 보기(plan)** 를 고르고 실행 → GitHub Actions의 `provision` 요약에서 `Plan: 5 to add`
4. 같은 양식으로 **실제로 만들기(apply)** → 요약에 끝났다고 나오는 것
5. (DNS를 이은 뒤) 만든 주소를 브라우저로 열어 소개 페이지가 뜨는 것

**다 찍은 뒤**
- 기다리는 시간은 잘라서 **1 ~ 2분**으로 줄인다. 소리는 뺀다.
- 화면에 **IP · 인스턴스 ID · 계정 번호 · 메일 주소 · 서버 주소**가 보이면 그 부분을 가리거나 잘라 낸다. 이 저장소에 올리면 누구나 본다.
- 파일 이름 `portal-demo.mp4`(H.264, 50MB 아래)로 `media/` 폴더에 넣는다. 발표 컴퓨터에서만 쓸 거면 저장소에 올리지 않고 그 폴더에 두기만 해도 재생된다.
- **만든 서버를 지운다:** 팀 저장소 Actions → `provision` → Run workflow → `destroy`, 확인 칸에 배포 이름을 한 번 더. DNS에 넣은 줄도 지운다.
- `index.html`을 열어 17장에서 재생되는지 본다. 대본의 "[녹화할 때 잰 시간으로 답할 것]"에 실제로 걸린 시간을 적는다.

## 쓰지 않았다고 적은 것 (지어내지 않는다)

- **RDS · DBMS · ERD:** 쓰지 않는다. 8장은 ERD 대신 데이터가 놓이는 자리(S3 세 칸)를 그렸다.
- **ELB:** 쓰지 않는다. 서버가 한 대다.
- **파이썬 · 자바 프레임워크:** 쓰지 않는다. 정적 사이트다.
- **웹 데모의 AI:** 부르지 않는다. AI는 개발(Claude Code)과 본 제품 Floe 앱 쪽 이야기다.
- **소개 페이지 서버(EC2 + EBS) · provision 자동 실행:** 11/24 기준 미리 보기(plan)까지. 그림에서 점선 · "예정"으로 둔다.
